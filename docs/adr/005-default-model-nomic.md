# ADR-005: Default embedding model — Nomic v2 MoE

- **Status:** Accepted
- **Date:** 2026-08-31
- **Decision:** Change the default embedding model from BAAI/bge-m3 to nomic-ai/nomic-embed-text-v2-moe
- **Supersedes:** BAAI/bge-m3 default (CLAUDE.md §4)

## Context

The project's free AI policy (openshift workspace,
conformite-embedding study E14.10) classifies
embedding models into 5 freedom levels. Only
levels 1-3 are eligible.

bge-m3 (BAAI) was classified **Level 4 — Opaque**:
- Training data includes Common Crawl content
  with unverified copyright
- Synthetic data generated by GPT-3.5
  (proprietary model dependency)
- No AI Bill of Materials (AIBOM)

This excludes bge-m3 from the project's policy.

## Options evaluated

### Nomic Embed v2 MoE — Level 2

- **License:** Apache 2.0
- **Data:** publicly published (contrastors repo)
- **Architecture:** 475M params, MoE 8 experts
  (305M active), 768 dimensions
- **Multilingual:** ~100 languages (FR/EN: yes)
- **Context:** 8192 tokens
- **MTEB:** competitive with bge-m3

### Granite Embedding R2 311M — Level 3

- **License:** Apache 2.0
- **Data:** governed by IBM, not published but
  documented (AIBOM, ISO 42001)
- **Architecture:** 311M params, 768 dimensions
- **Multilingual:** 200+ languages
- **Context:** 32768 tokens
- **MTEB Retrieval:** 65.2 (highest)

### bge-m3 — Level 4 (excluded)

- **License:** MIT (weights only)
- **Data:** opaque (Common Crawl, GPT-3.5 synth)
- **Architecture:** 560M params, 1024 dimensions
- **MTEB:** 63.0

## Decision

**nomic-ai/nomic-embed-text-v2-moe** as default.

Rationale:
1. **Level 2** — the highest freedom level among
   multilingual models. Only Nomic v1.5 is Level 1
   but it's English-only.
2. **Apache 2.0** with published training data
3. **Multilingual** including FR/EN
4. **Competitive quality** on MTEB benchmarks
5. **MoE architecture** — efficient (137M active
   params per token)

Granite R2 is documented as the Red Hat-aligned
alternative (Level 3, higher MTEB score).

bge-m3 remains documented as historical technical
reference (benchmark baseline) with an explicit
derogation note. Existing .db files indexed with
bge-m3 continue to work — model validation
prevents silent quality degradation.

## Consequences

- `DEFAULT_MODEL` changed in `embedder.py`
- Embedding dimension changes: 1024 → 768
- Existing .db files indexed with bge-m3 are
  incompatible (different model + dimension)
- Documentation updated throughout
- Users can still use bge-m3 via `LORE_MODEL`
  with documented derogation
