# Grooming E12.01 — Preprocessing tool design

- **Status:** Validé (design v2)
- **Date:** 2026-09-08
- **Context:** Platform self-service tooling,
  E14.17 recommendations, E3.06 preprocessing
  guide

## Problem

lore-mcp documents preprocessing best practices
(docs/preprocessing.md) but provides minimal
tooling. Consumers have raw sources in various
formats (PDF, HTML, DOCX, markdown) that need
conversion and cleaning before indexing. The
manifest should declare sources abstractly, not
depend on local filesystem layout.

## Design principles

1. **Manifest is source of truth** — declares
   sources by identity, never modified by lore-mcp
2. **Manifest is abstract** — entries are not
   file paths or URLs. `orig` (original file) and
   `path` (output) are generated if absent
3. **One `--docs-base-dir`** — all subdirs are
   relative to it
4. **Enriched manifest is a copy** — lore-mcp
   produces a `-prep` suffixed manifest with
   computed fields

## Manifest format

### User-authored manifest (read-only)

```yaml
collection: openshift-libre
level: libre

sources:
  # PDF source — orig in orig-subdir
  - orig: architecture.pdf
    license: Apache-2.0

  # HTML source with rename
  - orig: guide.html
    path: project-guide.md
    author: RC

  # Remote source — fetched via URL
  - url: https://example.com/spec.pdf

  # Already markdown — clean only
  - orig: notes.md
    title: Release Notes
```

### Field resolution cascade

| Field | If absent | Example |
|-------|-----------|---------|
| `orig` | Basename of `url`. Neither → error | `spec.pdf` |
| `path` | Basename of `orig` with `.md` ext | `architecture.md` |
| `title` | Extracted from document after conversion (front matter or first heading) | |
| `author` | Extracted from front matter | |
| `license` | Extracted from front matter | |
| `date` | Extracted from front matter | |

Biblio fields: Dublin Core names (ISO 15836).
License values: SPDX identifiers.

### Enriched manifest (generated, read-only)

Suffix: `-prep`. `manifest.yaml` → `manifest-prep.yaml`

```yaml
# manifest-prep.yaml — generated by lore-mcp preprocess
collection: openshift-libre
level: libre

sources:
  - orig: architecture.pdf
    path: architecture.md
    title: Architecture Guide
    author: RC
    license: Apache-2.0

  - orig: guide.html
    path: project-guide.md
    title: Project Guide
    author: RC

  - orig: spec.pdf
    path: spec.md
    title: Specification
    url: https://example.com/spec.pdf

  - orig: notes.md
    path: notes.md
    title: Release Notes
```

## CLI interface

```bash
# Preprocess: convert + clean
lore-mcp preprocess manifest.yaml \
  --docs-base-dir /corpus/ \
  --orig-subdir raw/ \             # optional, default: .
  --prep-subdir clean/ \           # optional, default: .
  --manifest-out manifest-prep.yaml  # optional, default: -prep suffix

# Lint: validate quality (uses prep-subdir)
lore-mcp lint manifest-prep.yaml \
  --docs-dir /corpus/clean/

# Build: index (uses prep-subdir)
lore-mcp build manifest-prep.yaml \
  --docs-dir /corpus/clean/ \
  --output-dir /db/
```

Path resolution:
- Originals: `<docs-base-dir>/<orig-subdir>/<orig>`
- Preprocessed: `<docs-base-dir>/<prep-subdir>/<path>`

## Architecture

```
Raw sources             Enriched manifest
(pdf/html/md/docx)      + clean markdown
      │                        ▲
      ▼                        │
┌─────────────────────────────────────────┐
│           lore-mcp preprocess           │
│                                         │
│  1. Resolve ──▶ 2. Parse ──▶ 3. Clean  │
│       │             │            │      │
│  manifest       Docling      NFC norm   │
│  field cascade  trafilatura  HTML strip  │
│  URL fetch      (passthru   img→alt     │
│                  for .md)   strip #     │
│  LLM tier 3                             │
│                                         │
│  4. Extract ──▶ 5. Dedup ──▶ 6. Validate│
│       │             │            │      │
│  title/author   SHA-256      lint gate  │
│  from content   MinHash                 │
│  front matter   Embedder                │
│                                         │
│  7. Enrich (opt-in, LLM)               │
│  8. Write manifest-prep                 │
└─────────────────────────────────────────┘

LLM usage (per E14.17):
- Step 2 tier 3: LLM for complex documents
- Step 5: Embedder for semantic dedup
- Step 7: Claude for contextual retrieval,
  Q&A mode, proposition indexing
- Steps 1,3,4,6,8: no LLM
```

## Pipeline steps

**Step 1 — Resolve** (E12.01):
Determine source files from manifest.
- Read manifest, apply field cascade
- If `url` and no local file: fetch
- If neither `orig` nor `url`: error

**Step 2 — Parse** (E12.03, depends on E6.06):
Convert to markdown.
- `.md`: passthrough
- `.pdf`, `.docx`: Docling (MIT, 97.9%)
- `.html`: trafilatura (GPL-3.0+, F1 0.966)
- 3-tier cascade (E14.17): md → Docling → LLM

**Step 3 — Clean** (E12.02, implemented):
Normalize text.
- Unicode NFC, HTML strip, NUL, image→alt,
  strip `#` (preserves code blocks)

**Step 4 — Extract metadata**:
Extract biblio from converted content.
- Front matter (title, author, license, date)
- First heading as fallback title
- Merge with manifest-declared values
  (manifest wins on conflict)

**Step 5 — Deduplicate** (E12.04):
- SHA-256 hash, MinHash+LSH, Embedder cosine

**Step 6 — Validate** (E12.07):
- Lint quality gate

**Step 7 — Enrich** (E12.09, opt-in LLM):
- Contextual retrieval, Q&A mode

**Step 8 — Write enriched manifest**:
- Write `manifest-prep.yaml` with all computed
  fields (path, orig, title, author, etc.)
- Write preprocessed `.md` files to prep-subdir

## Module structure

```
src/lore_mcp/preprocess/
├── __init__.py     # pipeline orchestration
├── resolve.py      # manifest field cascade, URL fetch
├── parse.py        # format conversion (Docling, trafilatura)
├── clean.py        # text normalization (implemented)
├── dedup.py        # deduplication
└── validate.py     # quality gate (wraps lint)
```

## Dependency impact

| Dependency | License | Step | Optional |
|-----------|---------|------|----------|
| docling | MIT | Parse | Yes (PDF/DOCX) |
| trafilatura | GPL-3.0+ | Parse | Yes (HTML) |
| datasketch | MIT | Dedup | Yes (MinHash) |

All compatible with AGPL-3.0. Parse deps are
optional extras.

## MVP sequence

1. **MVP1**: E12.01 resolve + E12.02 clean +
   manifest-prep generation. CLI scaffold with
   `--docs-base-dir`, `--orig-subdir`,
   `--prep-subdir`, `--manifest-out`. Field
   cascade. Markdown-only (passthrough parse).
   Immediate value, no new deps. **Partially
   done** (clean.py implemented, CLI needs
   rework for new options).

2. **MVP2**: E12.03 multi-format parsing.
   Docling + trafilatura. Core value: convert
   PDF/HTML to markdown. Depends on E6.06 study.

3. **MVP3**: E12.08 LLM capability. Transversal
   foundation for parse tier 3 and enrich.

4. **MVP4**: E12.04 + E12.07 dedup + quality
   gate. SHA-256 + lint integration.

5. **MVP5**: E12.05 + E12.06 PII + tables.

6. **MVP6**: E12.09 LLM enrichment.

7. **MVP7**: E12.10 build integration.
